## 0. 范围与结论

**做**：① 按需抓拍一张图并传到 PC；② 逐帧上传医学相关数据（遥测）。
**不做**：实时视频流（720p60 RGB888 = 1.33 Gbit/s，超过千兆可用带宽 957 Mbit/s，见评估文档 §1）。

**核心设计决策（让成本骤降的那一条）**：
> **抓拍图不从 DDR 读，改为在显示读流上持续维护一块 ERAM 缩略图；"拍照"= 冻结这块 ERAM 并读出去。**

由此得到三个连锁好处：

| 好处 | 说明 |
|---|---|
| **零额外 DDR 读口** | 不需要改 `mc_to_user_interface` 加 transaction tag（现有命令只有 1 bit 读/写标志，改造成本与风险都高） |
| **不需要冻结/暂停逻辑** | 不用碰 `video_in.v` 的 `I_display_pause`，显示始终流畅 |
| **与 P7 运动检测共用前端** | 都是 8×8 块下采样到 160×90，**一份硬件两个功能** |

代价对比：

| 方案 | DDR 新增读 | 需 tag 逻辑 | 逻辑增量 | 判断 |
|---|---|---|---|---|
| 从 DDR 读冻结帧 | +11.9~165.9 MB/s | ✅ | ~400 LUT + 高风险 | ❌ |
| **ERAM 缩略图** | **0** | ❌ | **~600 LUT + 12 ERAM** | ✅ **选它** |

## 1. 传输能力对照（决定用哪个物理层）

缩略图 160×90 RGB565 = **28,800 B**

| 物理层 | 有效速率 | 传一张缩略图 | 传 320×180 RGB565 (115 KB) | 传 720p 全彩 (2.76 MB) |
|---|---|---|---|---|
| UART 115200 | 11.5 KB/s | 2.5 s | 10 s | 240 s ❌ |
| **UART 921600** | **92 KB/s** | **0.31 s** ✅ | 1.25 s | 30 s ❌ |
| UART 3 Mbps | 375 KB/s | 0.077 s ✅ | 0.31 s ✅ | 7.4 s ⚠ |
| 100M 以太网 | 11.9 MB/s | 0.002 s ✅ | 0.01 s ✅ | **0.23 s** ✅ |

**结论**：
- **遥测**：3 包/帧 × 60 帧/s × ~40 B = **7.2 KB/s** → **115200 就够**，占用 0 面积（UART 板载）
- **抓拍缩略图**：**921600 足够**（0.31 s）→ **这条路完全不依赖开发板原理图**
- **720p 全彩原图**：只有以太网能救（0.23 s）→ 列为条件触发的升级项

## 2. 数据模型与协议（字节级定义，与 `mdlink.py` 完全一致）

### 2.1 物理帧（UART 与 UDP 共用一个 payload 格式）

```
UART 物理帧:  AA 55 | LEN(2, LE) | PAYLOAD(LEN) | CRC16(2, LE)
              SYNC   长度          载荷             校验
   CRC16-CCITT: poly=0x1021, init=0xFFFF, 不反射, 末异或 0
   LEN ≤ 1024（UART）; UDP 时 LEN ≤ 1448（MTU 1500 - IP/UDP 28）
   PC 端用"找同步字 + CRC 校验"做重同步（已实测：注入 14 字节垃圾后 479 包 0 错）
```

### 2.2 PAYLOAD = 遥测头(16 B) + 变长体

```
遥测头 (16 B, 小端)
 off size field        说明
 0   2    magic        0x4D44 = 'M''D'（Medical Data）
 2   1    version      0x01
 3   1    type         见下表
 4   2    frame_id     帧号，回绕
 6   4    ts_ms        采集时刻的 ms 计数（板内 32bit 计数器）
 10  2    latency_ms   端到端延迟（来自实施方案 P3 的 frame_tag）
 12  1    mode         当前算法模式
 13  1    flags        自检状态位压缩
 14  2    body_len     体长度
```

**mode 编码**（与实施方案的算法模式对齐）
| 值 | 模式 | 值 | 模式 |
|---|---|---|---|
| 0 | RAW 原图 | 5 | DETECT 目标检测 |
| 1 | GRAY 灰度 | 6 | MOTION 运动检测 |
| 2 | EDGE 形态学边缘 | 7 | VITAL 生命体征 |
| 3 | BIN 二值化 | 8 | SELFCHECK 自检页 |
| 4 | CARTOON 卡通化 | | |

### 2.3 五种 type

**type=0x01 STATUS（体 16 B）** — 每帧一条
```
u16 luma_mean       平均亮度 0..255（Q0.8 或整数）
u16 clip_permille   过曝像素比例 ×10（12 = 1.2%）
u16 ae              当前曝光寄存器值 (0x3e00~0x3e02 合成 16bit)
u16 ag              当前增益寄存器值 (0x3e08~0x3e09 合成 16bit)
u16 fps_x10         实测帧率 ×10（600 = 60.0 fps）
u8  status_bits     自检状态位：bit0 MIPI / 1 CSI / 2 ISP / 3 DDR写 / 4 DDR读 / 5 HDMI / 6 摄像头配置完成 / 7 DDR校准完成
u8  reserved
u32 drop_cnt        丢帧计数
```

**type=0x02 DETECT（体 24 B）** — 有目标时发
```
u8  class_id        0=无 1=橙 2=红 3=蓝 ...
u8  count           目标数量
u16 x0,u16 y0,u16 x1,u16 y1    包围框（像素坐标）
u16 fill_permille   填充率 ×10（判断形状用）
u16 area_px         面积/100（省字节，PC 端 ×100）
u8  shape_id        0=未知 1=圆 2=方 3=条形
u8  reserved
u32 reserved2
```

**type=0x03 MOTION（体 16 B）** — 有运动时发
```
u16 motion_count    运动块计数
u16 x0,y0,x1,y1     运动包围框
u16 motion_th       当前阈值
u16 tiles_hit       命中 tile 数（16×9=144）
u16 reserved
```

**type=0x04 VITAL（体 16 B）** — 医学数据主体
```
u16 hr_x10          心率 ×10 BPM（720 = 72.0 BPM）
u16 roi_mean        肤色 ROI 平均亮度
u16 roi_ac          ROI 交流分量幅度（×1000）
u8  quality         信号质量 0..3（0=不可用，PC 端据此决定是否显示 BPM）
u8  roi_id          ROI 编号
u16 rx0,ry0,rx1,ry1 肤色 ROI 包围框
```

**type=0x05 IMAGE（体 12 B 头 + 数据）**
```
u16 frame_seq       抓拍序号
u16 chunk_idx       分片序号
u16 chunk_total     总分片数
u16 width,height    图像尺寸
u8  format          0=RGB565 1=RGB888 2=GRAY8
u8  flags           0
u8  reserved
u8  data[]          本片数据
```

### 2.4 数据量与速率核算

| 内容 | 单包大小 | 频率 | 速率 |
|---|---|---|---|
| STATUS | 32 B | 60/s | 1.9 KB/s |
| VITAL | 32 B | 60/s | 1.9 KB/s |
| DETECT | 40 B | 有目标时 60/s | 2.4 KB/s |
| MOTION | 32 B | 有运动时 60/s | 1.9 KB/s |
| **遥测小计** | | | **≈ 8 KB/s**（含 UART 帧开销约 10 KB/s） |
| IMAGE | 28.8 KB | 按需（人工按键，≤1/s） | 峰值 92 KB/s @921600 |

→ **115200 就能跑遥测；921600 才能顺带传图。默认设 921600。**

> ⭐ **表下说明：组包/命令解析可迁到片上 RISC-V MCU（2026-09-18 晚新增）**
>
> 安路官方 **FutureDynasty (FD)** 软件"**已支持 Softcore、SF1、DR1、PH1P35 等多种平台的项目创建**……实现 **ARM、RISC-V** 工程的编译与调试"
> （<https://www.anlogic.com/product/software/5.html>）。TD 安装内亦有配套 IP：`RISCV_Processor_System_F9F0D0P0`（含 `soc_plat.html`/设备树/BSP 模板）、`AHB_Riscv_Core`；
> 例程 MCU 参数（`lab_ex3_osd/user_source/ip_source/MCU/.params_MCU.txt`）：Core 300 MHz / AHB 150 MHz / UART0,1 @300~921600 / AHB+APB 可用。
> → 上表 **`tlm_pack`（~350）+ `uart_tx`（~120）+ `uart_rx`（~150）+ `md_ctrl`（~120）** 这一组**纯控制流**
> （组包/CRC16/分片状态机/串口命令解析/菜单）可改为**软件实现**，**FPGA 侧只留一个 AHB/APB 寄存器窗口，
> 预计合计省 ~500 LUT**（MCU 还与 FPGA 共享同一片逻辑资源，不额外占 FPGA 面积）。
>
> **合规边界**（Q&A：赛题指标要求部分必须在 FPGA 上实现）：**算法层绝不下放 MCU**——下采样/灰度/边缘/颜色检测/运动检测
> 全部留在 FPGA 逻辑里；而**串口协议解析、组包、分片、菜单不是赛题指标**，属于"决策/交互层"，可以放 MCU。
>
> **风险（两点，均未验证）**：① 需确认 **FD 的安装与授权**；② 需确认"**固件与 bitstream 一起固化**"的流程，
> 否则上电不会自动加载固件，直接违反"上电即跑"。
>
> **建议**：走**独立支线**——先花 1~2 天验证"FD 装上 + MCU 读写寄存器 + 固化"，成功再把上表四个模块逐步迁过去；
> 失败则本文的 FPGA 逻辑版本照做，主线不受影响。依据：`doc/analysis/增量分析与新思路-2026-09-18.md` §1.4 / §2.2。

### 3.2 PLL / 时钟

| 用途 | 时钟 | 来源 |
|---|---|---|
| 打包逻辑 | **新建 `MD_CLK` = 50 MHz**（PLL 新开一个输出，VCO 1500/30） | 与 75M HDMI 域用异步 FIFO 隔离；也可直接复用 `pll_clk_100m`/50M。**补（2026-09-18 晚）：PLL 共有 7 个输出、例程只用了 4 个，C2/C3/C6 的使能位接 0 → 可直接启用，不额外占 PLL**（`ip_source/PLL/PLL.v`；`33_ethernet_udp_led` 亦用 C0=125 MHz / C1=125 MHz(90°) / C2=25 MHz，没有多占 PLL） |

> 打包域与 HDMI 域之间只需要跨**窄总线**（8 bit 数据 + 少量 valid），用 `FIFOF9F0D0P0` 或 `Soft_FIFO_3.0` 即可。**禁止多 bit 直接打拍。**

### 3.3 关键模块接口（Verilog 端口）

```verilog
// ① 8×8 块下采样（显示读流旁路，零 DDR 成本）
module blk_downsample #(
    parameter IMG_W = 1280,
    parameter IMG_H = 720,
    parameter BLK   = 8
)(
    input               I_clk,          // HDMI_PIXEL_CLK 75MHz
    input               I_rst_n,
    input               I_de,
    input               I_frame_start,  // vsync
    input      [23:0]   I_rgb,          // 显示读出的像素
    input               I_rd_en,        // 与 I_de 同拍，= 显示读使能
    output reg          O_blk_valid,    // 每完成一块拉高一拍（约 60*160*90/.... ）
    output reg  [7:0]   O_blk_x,        // 0..159
    output reg  [7:0]   O_blk_y,        // 0..89
    output reg  [15:0]  O_blk_rgb565,   // 块中心像素（缩略图）
    output reg  [7:0]   O_blk_luma      // 块内 64 像素平均灰度（运动/统计）
);
// 实现要点：
//  · 行内 8 像素累加 luma（3 级加法树）
//  · 列方向累加器 160 项 × 16bit 放 LUTRAM（1 块），每 8 行清零
//  · 块中心取 (BLK/2, BLK/2) 那个像素转 RGB565 —— 纯位操作，无乘法
//  · 块平均 = 累加值 >> 6（64 个像素），纯移位
```

```verilog
// ② 缩略图缓冲 + 抓拍冻结
module thumb_capture #(
    parameter TW = 160,
    parameter TH = 90
)(
    input               I_clk,
    input               I_rst_n,
    input               I_capture_req,     // 按键 或 下行命令（已同步到本域）
    input               I_blk_valid,
    input      [7:0]    I_blk_x,
    input      [7:0]    I_blk_y,
    input      [15:0]   I_blk_rgb565,
    // 读出侧（冻结期间使用同一端口）
    input               I_rd_en,
    output reg  [15:0]  O_rd_data,
    output reg          O_frozen,          // 1 = 已冻结，可以读
    output reg  [15:0]  O_frame_seq
);
// 状态：LIVE（持续覆盖写） --capture_req--> FROZEN（停写，可读） --发完--> LIVE
// 单端口 RAM 即可：写与读互斥
// ERAM: 160*90*16 = 230,400 bit = 12 块
```

### 3.4 抓拍控制流

```
IDLE/LIVE : 缩略图每帧被覆盖更新（几乎零成本，因为下采样本来就在跑）
   │
   ├─ 触发源（任一）：① 板上按键 K2   ② UART 下行命令  ③ OSD 菜单
   ▼
FROZEN    : thumb_wr_en = 0，锁存 frame_seq，OSD 显示 "CAPTURED #n / SENDING..."
   ▼
SENDING   : 从 ERAM 顺序读出 → img_chunk 分片 → tlm_pack 组包 → UART/以太网
            · 分片大小：UART 1000 B / UDP 1448 B
            · 总片数：28800/1000 = 29 片（UART）
   ▼
DONE      : thumb_wr_en = 1（恢复实时更新），OSD 显示 "DONE (0.31s)"
```

**注意**：冻结期间缩略图不更新，但**显示的实时画面不受影响**（缩略图和显示是两条独立通路）。所以界面上只看到 OSD 提示，画面照常。

## 5. 医学数据怎么做实：图像法心率（rPPG）

**为什么选这个**：不需要任何额外硬件（这是关键——接心电前端的风险在评估文档里已经论证过），复用 P5 已有的肤色检测，而且让"医学数据"从"变量改名"变成真的有医学含义。

### 5.1 算法链（全部在帧率域，60 Hz）

```
① 肤色掩码（复用 P5 的 YCbCr 分类）
     Cr ∈ [133,173] 且 Cb ∈ [77,127]  → skin
② 逐帧累加：sum_skin += luma, cnt_skin += 1        （每帧 tuser 清零）
③ 帧末 mean = sum_skin / cnt_skin
     ★ 不要为此新增除法器：复用 P6 AWB 重构时做的那个【共享慢速除法器】
       或者：用 (sum_skin * recip(cnt_skin)) >> 16 的倒数 LUT
       再或者：先直接用 sum_skin>>K 近似（K 由 cnt 的粗略档位决定），
               因为 rPPG 关心的是相对变化，绝对标定不重要
④ 去直流（IIR 高通，约 0.15 Hz @60Hz）
     dc <= dc + ((mean - dc) >>> 6)
     ac  = mean - dc
⑤ 带通 0.7~4 Hz（42~240 BPM）
     一阶低通：lp <= lp + ((ac - lp) >>> 3)        ≈ 4~5 Hz
     带通输出 bp = lp - dc2（再一个慢高通）
⑥ 峰值检测：bp 过零上升沿计数（加滞回，避免噪声误计）
     4 秒滑动窗口内计 N 个峰 → BPM = N * 15
⑦ quality（0..3）：
     ac 幅度落在合理区间 [ac_min, ac_max] 且 峰值间隔的方差小 → 高
     否则降级；quality=0 时 PC 端不显示 BPM，只显示 ROI 均值趋势
```

### 5.2 资源

| 部分 | 估算 LUT |
|---|---|
| 肤色累加 | 50 |
| 去直流 + 带通（移位加法 IIR，无乘法） | 150 |
| 峰值检测 + 窗口计数 | 120 |
| quality 评估 | 80 |
| **合计** | **~400** |

### 5.3 ⚠ 诚实的限制说明（必须写进答辩材料）

- rPPG 要求**被测部位基本静止** + **光照稳定** + **肤色像素占比足够**
- 现场演示时建议：把手背/手指靠近镜头保持不动 10 秒，光照不要直射
- **必须在 OSD 与 PC 端同时标注"算法演示，非医疗用途"**
- 降级策略：`quality = 0` 时只上传 ROI 均值与 AC/DC 比值作为"生理指标趋势"，**不声称 BPM**

> 这个降级策略很重要：它让功能在"测不准"的时候依然是一个有价值的数据通道，而不是一个失败的演示。

## 7. 面积预算与冲突处理

> ⚠ **基线已按本机 TD 6.2.1 SP1(178840) 重测**（同 RTL 同约束，对照官方 6.2.168116）：
> slices ~~14,852 (70.00%)~~ → **14,731 (69.43%)**、lut6 ~~12,669~~ → **12,606**；ERAM 40 / DSP 9 不变；
> **DDR `usr_clk` 域裕量 0.576 ns → 2.311 ns**（大幅改善，约 3 倍余量）、`HDMI_SERIAL_CLK` 0.336 → 0.751 ns、
> **`HDMI_PIXEL_CLK` 0.103 ns → 0.006 ns（恶化 97 ps，几乎贴线）**。
> **结论：P1 之后约剩 2,400 LUT 的量级判断基本不变，但新的主要时序约束是 HDMI 像素域，而不是 DDR 域。**
> 依据：`doc/analysis/增量分析与新思路-2026-09-18.md` §1.2。

P1（Logo 搬 ERAM）之后约剩 **2,400 LUT** 余量，而竞赛主线的 P2~P7 已经要吃掉约 2,650 LUT。本模块再要 940~1,340 LUT，**必然超**。

**优先级（按"得分÷成本"排）**

| 优先级 | 内容 | LUT | 判断 |
|---|---|---|---|
| **必做** | `uart_tx/rx` + `tlm_pack` + `md_ctrl`（纯遥测） | ~620 | 成本最低，直接命中 slide 24 的"状态监控" |
| **必做** | `blk_downsample` | ~200 | **和 P7 运动检测共用**，边际成本接近 0 |
| **推荐** | `thumb_capture` + `img_chunk`（抓拍传图） | ~270 + 13 ERAM | 命中"上位机配置/监控" + 演示效果直观 |
| **推荐** | `vital_rppg` | ~400 | "医学数据"的实质内容，支撑应用价值 |
| **延后** | `eth_tx_100m` | ~800 | 只有需要 720p 全彩原图时才做；且需原理图 |

**ETAM 预算**（总 108 块，lab3 已用 40）

| 用途 | 块数 |
|---|---|
| Logo ROM（P1） | 6 |
| OSD 字模 + 文本缓冲（P3） | 2 |
| 运动检测缩略帧（P7） | 6 |
| **缩略图抓拍（本模块）** | **12** |
| 组包/分片 FIFO | 3 |
| 小计新增 | 29 |
| **合计** | **69 / 108** ✅ |

**若面积不够，按此顺序砍**：
1. 砍 P4 的 3×3 中值滤波（约 400 LUT，卡通化降质但可接受）
2. 砍 P7 运动检测（本模块的 `blk_downsample` 保留，缩略图不受影响）
3. `vital_rppg` 降到只报 ROI 均值与 AC/DC（省 ~200 LUT）
4. 砍 P5 的 shape_id 判决
5. **最后才砍抓拍传图**——它是本模块的核心卖点
