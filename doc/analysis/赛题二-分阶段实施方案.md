> ## 🔔 v1.3 更新（2026-09-18 第三轮）：**P1 的内容与依据被改写**
>
> 依据：**`doc/analysis/核验与纠偏-2026-09-18第三轮.md`**（⭐ **冲突时以它为准**）。
> 回到 TD 原始报告与 RTL 原件逐条核验后，本文档有 **4 处需要修订**：
>
> **① ⚠ 真正的关键路径在 MIPI/ISP 域，不是 HDMI 域。**
> lab3 时钟表实测：`MIPI_RX_BYTE_CLK` **+7.869 ns**（Fmax 113.649 MHz）、`usr_clk` +0.576 ns、
> `HDMI_PIXEL_CLK` **+0.103 ns**、`HDMI_SERIAL_CLK` +0.336 ns。
> **lab3 与 lab2 的最差路径都在 MIPI 域**；lab2 的 slack 仅 **1.451 ns**，
> 路径是 `u_awb/mult5`（DSP 输出）→ `u_edge_detect_96/O_tdata_reg`，**14 级逻辑、其中 10 级 ADDER**。
> ⇒ **P1 应拆成：P1a（AWB 重构，打断这条最紧路径）+ P1b（Logo/OSD）+ P1c（ISP 域提速验证）。**
> 详见第三轮文档 §1、§10。
>
> **② ❌ "Logo 吃掉 2,495 LUT / 搬走省 −2,399 LUT" 作废。**
> 该 2,495 是**位密度反推的估算，TD 从未报过**。真实口径：
> RTL 级 `anlogic_logo_rom` = **38,479 个 gate（不是 LUT）**；gate 级该模块**已被吸收**；
> 布线后 `u_hdmi_mixer` 整模块 **2,572 LUT**（`u_anlogic_logo_rom` 单列 54 LUT）。
> 可信差分：`u_hdmi_mixer` **46 → 2,572 LUT**（lab1→lab3）、全设计 slices **12,358 → 14,852**。
> ⇒ **P1b 的主收益是时序（拿回 `HDMI_PIXEL_CLK` 裕量），不是省面积；面积收益必须 P&R 实测。**
> （`tools/gen_logo_mif.py`、`tools/logo_rom/*` 已按此更正并重新生成。）
>
> **③ ❌ DSP 规格作废。** 官网是"**27×18, 9×9**"；IP 生成器出厂默认 **18×18 / Z,P=54**；
> `dsp_macro_0.v` 内部把 A/B **补到 27 bit**。**"26×26 → 53 bit"是 RTL 模板的 parameter 默认值，不是器件规格。**
> 且 `SEL` 是**逐拍切换、不是同拍并行** ⇒ 一个 DSP 每拍只出 1 个乘积。
> 详见第三轮文档 §11。（**好消息**：18×18 对 8 bit 图像算法完全够用，AWB 8→2 个 DSP 的结论不变。）
>
> **④ ⚠ DDR 实际跑 DDR2-533，不是 DDR2-1066。**
> IP 参数写 `PH1P_REF_CLK 100.0` / `tCK 1876`，但 `ph1p35_324_ddr_wrapper.v:79` 把 `.ref_clk(I_sys_clk)`
> 接到了 **50 MHz** ⇒ VCO = 50/3×32 = 533.3 MHz ⇒ `ddr_clk` = **266.667 MHz**、`mcu_clk` = 25.397 MHz
> （**与 `final_timing.rpt` 实测逐位吻合**）。
> ⇒ **引脚峰值 = 用户口 = 1,066.7 MB/s，1:1 无余量差**（原 §0.5-C1 的"2,133 MB/s / 2 倍余量"作废）。
> **地址单位已定论**：每拍 `+8`、一拍 128 bit ⇒ **单位 = 2 B**，25 bit × 2 B = 64 MiB ✓，帧槽 7,000,000×2 B = **14 MB** ✓。
>
> **⑤ 其它需要更正的旧表述（见第三轮文档 §3、§8.3、§9）**
> - `video_out` **有双向握手**（`.O_video_out_rd_busy` + `.I_video_in_wr_busy` 都在）⇒ "写饿死读"风险降级，换来"互锁活锁"风险。
> - `user_source/constraints_source/timing.sdc` 是 **0 字节空文件**；真正生效的是 `td_project/camera_to_dsi_display.sdc`（17 行）。
> - **写入指针/读指针固定差 2**（`rp = wp+2`），且 `I_mipi_rx_error` 被顶层硬接 `1'b0`（坏帧重写机制已禁用）。
> - **`32_cs500` 无法编译**（`SYN-8511`，`ddr_ip` 端口全空接），其 `timing.sdc` 四条约束全失效，
>   视频链路也是断的 ⇒ **只能当 RTL 素材库**；其 `bound_cut.v` **是"涂黑边框"，不是包围框**（原 §1.7 表述要改）。

## 0. 怎么用这份方案

### 0.1 三条交付线，按你的时间选一条

| 交付线 | 包含阶段 | 覆盖赛题条目 | 累计估计工作量 |
|---|---|---|---|
| **MVP（保底）** | P0 → P1 → P2 → P3 → P4 | 基础 4/4 + 扩展(1) + 高阶(3) | **约 4 周** |
| **标准（推荐）** | MVP + P5 → P6 | 再加 扩展(2) + 高阶(2)(5) | **约 7 周** |
| **完整（冲高分）** | 标准 + P7 → P8 | 再加 高阶(4) + 自检/固化/演示 | **约 10 周** |

> 估时按"1 人全职、有板卡和摄像头、TD 已装好"计。2 人可并行时约缩短 35%（建议按 P1/P5 与 P3/P4 两条独立支线并行）。

### 0.2 三条铁律（整个项目都靠它们）

1. **每改一个模块，立刻跑一次 P&R 并记录趋势。**
   `tools/run_regression.ps1` 就是为这条纪律写的。绝不"攒着一起加"——官方 lab2 和 lab3 从未被同时构建过，合起来才两天就暴露了 DDR 域 0.576 ns 的问题。
2. **先修时序、再加功能。**
   lab3 基线本身就不通过门禁（HDMI 域只有 **0.103 ns**）。第一步不是加算法，是把 Logo 从 LUT 搬进 ERAM。
3. **一切以代码和 TD 报告为准，文档一律不信。**
   官方文档写 1024×600，代码是 1280×720；写 `EDGE_TH=132`，代码是 80；写"Alpha 混合"，实现是色键。

### 0.3 每个阶段的固定动作（模板）

```
① 读上一阶段的 trend.csv，确认门禁通过
② 按本阶段的"步骤"逐项改 RTL / 加 IP
③ 上板验证本阶段的"现象"（用自检模式或 ChipWatcher）
④ 跑 run_regression.ps1 -Stage Pn -Tag "..." -Targets @{...}
⑤ 门禁通过 → 打 tag（git tag Pn-ok）→ 进下一阶段
   门禁失败 → 按"回退方案"处理，不要带着失败往下走
```

> | 项 | 判据 | 验收方法 |

> | **AWB 输出率** | **≤ 4.34 拍/字** | `sim/p1b/tb_awb_rate3.v` |

> 详见 `doc/analysis/撕裂根因报告-awb吞吐回归.md` 与
> `doc/analysis/复盘-撕裂事故与全部方案回归-2026-09-20.md`。

### 阶段 P3 — OSD 文本子系统 + 延迟可视化（4~5 天）

### 阶段 P5 — 颜色目标检测 + 包围框 + 坐标（6~7 天）　→ 扩展(2) + 高阶(2)

**目标**：识别特定颜色目标，叠加检测框、类别、坐标、数量。

**架构决定（重要）**：**统计与叠加全部放在 `HDMI_PIXEL_CLK` 域，旁路 `video_out` 的显示读数据流。**
理由：① 零额外 DDR 带宽；② 检测框天然与显示的像素共位，不会错位；③ 避免把大块统计结果跨时钟域搬。代价是框比物体晚一帧（16 ms），肉眼不可辨。

**步骤**

1. **YCbCr 转换（CSD 移位加法，不用 DSP）**
   ```
   Y  = (77R + 150G + 29B) >> 8
   Cb = ((-43R - 85G + 128B) >> 8) + 128
   Cr = ((128R - 107G - 21B) >> 8) + 128
   ```
   常量乘法用 CSD；4 px/拍 × 3 通道 = 12 个常量乘法，每个约 2~4 LUT → **总计约 40 LUT**。
2. **颜色分类**：对每个像素做 (Cb,Cr) 矩形阈值判决，输出 2 bit 类别（橙 / 蓝）。**约 150 LUT。**
3. **tile 统计**（不要做完整连通域标记，two-pass union-find 在 720p 上太贵）
   - 画面分 **16×9 = 144 个 tile**（每 tile 80×80 像素）
   - 每 tile：8 bit 命中计数（饱和）+ 1 bit 标志 → 144×9 = 1,296 FF（FF 只用了 31%，很宽裕）
   - 计数按 tile 行滚动，一个 tile 行结束后即可比较
4. **包围框**：遍历 144 个 tile 的标志，求 `tile_xmin/xmax/ymin/ymax` → 乘 80 得到像素坐标（用移位加法：80 = 64+16）。
5. **画框 + 文字**
   - 框线生成：在 HDMI 域对 `x/y` 与四个边界比较，输出 4 条 2 像素宽的线（**约 200 LUT**）
   - 文本：写 `TARGET: ORANGE (312,208)-(472,368) N=3` 到文本缓冲
6. **形状判决（"识别"）**：用填充率 `fill = count / (w*h)` 与长宽比区分 圆形/方形/条形，产生"类别"文字。

**门禁**：拿橙色物体进入画面 → 出现框 + 正确坐标 + 计数；移出画面 → 框消失且无残留（**必须验证"无残留"**，否则说明 frame 边界清标志漏了）。

**回退**：若 tile 统计的边界框抖动 → 加时域平滑（`bbox_new = bbox_old + (bbox_target - bbox_old)>>2`）或要求连续 2 帧命中才显示。

### 阶段 P7 — 运动目标检测（零额外 DDR 带宽）（5~6 天）　→ 高阶(4)

**目标**：硬件帧差法运动检测 + 运动区域框 + 计数。

**架构决定**：**不新增任何 DDR 事务。** 全分辨率帧差要再读 165.9 MB/s，会让用户口占用从 31% 升到 47%，而且单端口仲裁没有 transaction tag，容易饿死显示。

**方案：8×8 块平均 + ERAM 存上一帧**
```
① 在 HDMI_PIXEL_CLK 域，旁路 video_out 的显示读流（与 P5 共用同一个 tap）
   每 8×8 像素块累加灰度 → 得到 160×90 = 14,400 个缩略亮度
② 缩略帧存 ERAM：14,400 × 8 bit = 115,200 bit ≈ 6 块 ERAM（存"上一帧"）
   当前帧用滚动累加器（一个块累完就比，不需要整帧缓冲）
③ 比较：|cur - prev| > TH → 运动
   建议用 sigma-delta 背景建模代替简单帧差（抗光照突变）：
       bg += (cur > bg) ? +1 : -1      // 只需加减和比较
       motion = |cur - bg| > TH
④ 3×3 形态学（腐蚀→膨胀）去噪，在 160×90 上做，极便宜
⑤ 输出：运动 tile 图 → 求包围框（×8 映射回原图）→ OSD 画框 + "MOTION: 1234"
⑥ 帧末把 cur 写入 prev（真双口 ERAM 或乒乓两块）
```

**代价**：约 **+400 LUT + 6~10 块 ERAM**，**DDR 带宽增加 = 0**。

**门禁**：挥手 → 出现运动框与计数；静止 → 计数归零、无框；缓慢改变光照 → 不应误报（验证 sigma-delta 生效）。

**回退**：若块平均的边界效应导致框抖动 → 阈值加滞回（进入阈值 20，退出阈值 12）。

#### ★ 吞吐验收（2026-09-20 新增 —— 本轮撕裂事故的直接教训）

**触发条件**：只要某阶段**把数据通路的并行度改成"分时/复用"**（或减少了每拍像素数），
就必须在综合之前先做吞吐验收。**资源差分不能替代吞吐验收。**

| 项 | 判据 | 工具 |
|---|---|---|
| awb 输出率 | **≤ 4.34 拍/字** | `sim/p1b/tb_awb_rate3.v` |
| FIFO 丢字 | **= 0**（`drop_cnt = fifo_wr & fifo_full`） | 同上 |
| 激励形态 | **真实突发**：每行 **320 字连发 + 51 拍空档** | 同上（`GAP=51`） |

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File tools\run_d4_ab_launcher.ps1 -Which both
# 日志：_stage\d4_rate2\<ref|fixed>\sim.log
```

> ⚠ **两个必须避开的坑**：
> 1. **激励必须是突发形态。** 按均匀流灌数据会把 FIFO 写侧摊平，得出"平均达标"的**假结论**。
>    真实写侧形态来自 `signal_delay.v:76-80` 的 `rd_valid` 窗口。
> 2. **丢字是静默的。** `soft_fifo_al_f58e8b3e1f3d.v:77` 是
>    `wr_en_s = (!full_flag) & we` —— FIFO 满时直接丢弃写入，**无溢出标志、无报错**。
>    所以必须自己在仿真里数 `fifo_wr & fifo_full`。
>
> **反面教材（P1a）**：只做了资源差分（DSP 8→2），漏掉吞吐验收，
> 结果 awb 吞吐 1.34 → 5.00 拍/字，FIFO 每行净积压 240 字、两行溢出，
> **上板撕裂**。详见 `doc/analysis/撕裂根因报告-awb吞吐回归.md`。
