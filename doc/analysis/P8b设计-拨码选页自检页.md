# P8-b 自检页设计（拨码选页 · 零新增 OSD 面积）

> 2026-09-27 定稿。选 b 方案的理由与依据写在 §1；实现细节在 §3。

---

## 1. 为什么用**拨码开关选页**，而不是按键翻页

**按键是"事件"，拨码是"电平"** —— 这一个区别消掉了三样东西：

| 按键翻页需要 | 拨码选页是否需要 |
|---|---|
| 翻页状态机（记住当前第几页） | ❌ 不需要（电平直接决定） |
| 消抖（20 ms 计数器 + 边沿检测） | ❌ 不需要（电平稳定后自然稳定） |
| "按下期间画面跳/连翻"的处理 | ❌ 不需要 |

⇒ 实现量从"一个小状态机 + 消抖"降到**一个纯组合 mux**，而且**面积近乎为零**（不需要新增组合链，只在已有文字链前面换个数据源）。

**更要紧的是**：`tools/check_crit_path.py` 实测本设计有**两条几乎并列的关键路径**
（HDMI 12.93/13.33 ns 与 MIPI 16.19/16.67 ns，后者在厂家 `u_awb` 里），
而 **slice 已到 76%** ⇒ 面积比时序更紧。P8-b "复用已有 OSD 行、不新增区域"
正好压在面积这一侧。

### 1.1 板上可用的开关（实测引脚表，非推测）

来源：`doc/analysis/_extract/DX_HX1P35B引脚分配汇总.txt` 第 127~129 行

| 开关 | 引脚 | 现状 |
|---|---|---|
| **SW1** | **A4** | **空闲** |
| **SW2** | **B4** | **空闲** |
| **SW3** | **E11** | **空闲** |
| **SW4** | **D11** | **空闲** |
| SW5 | — | 已用：蜂鸣器使能开关 |
| SW6 | — | 已用：数码管 / 双色 LED 选择 |

⇒ 4 个空闲开关 = **16 种页选**，本次只用 SW1/SW2 做 4 页，SW3/SW4 留给后续
（例如 Flash 固化模式选择、运动阈值档位）。

## 2. 页内容规划（4 页，SW1/SW2）

**核心约束：不新增任何 OSD 区域。** 页切换只改变**已有 9 个区域中"文字行"的数据源**，
框（目标框/运动框）与状态条**所有页都照常显示**（它们是实时结果，不该被页选藏掉）。

| 页 | SW[2:1] | 第 2 行（诊断行） | 第 3 行（AE 行） | 第 4 行（目标坐标） | 第 5 行（运动计数） |
|---|---|---|---|---|---|
| **0** | 00 | `B E0 W xxxxx C xx/xx`（现状） | `A 07C6 G 59 L 93`（现状） | `BLK xxxx,yyy`（现状） | `M xxx,yyy N xxxx`（现状） |
| **1** | 01 | 流水线配置：模式/灰度算法选择 | AE **内部量**：目标值 / 方向 / 下发次数 / 饱和位 | 目标检测参数：`CB_MIN/CB_MAX/CR_MIN` 十六进制 | 运动参数：`MOT_TH / BG_STEP / MIN_BLK` |
| **2** | 10 | 计数健康：FIFO 满标志累计、MIPI 错误位 | 亮度统计：`ΣY` 高 16 位 / 过曝像素数 | 帧计数（当前 `安路 CNT` 的原始值） | 运动原始块数 vs 腐蚀后块数（`raw` 与 `blk` 分开） |
| **3** | 11 | 保留（版本号 / 构建日期编码） | 保留 | 保留 | 保留 |

**为什么页 2 是"自检"的核心**：G1/G2 那两个开口（`w155_d512_fifo` 满标志计数、
`I_mipi_rx_error` 硬接 `1'b0`）一直是已知遗留项 —— **页 2 把它们变成可观测的**。
"把看不见的风险变成屏幕上的一行字"正是自检页的意义。

## 3. 实现（RTL 触点，共 4 处）

| # | 文件 | 改动 |
|---|---|---|
| 1 | `user_source/constraints_source/pin.adc` | 新增 `I_sw[0]=A4`、`I_sw[1]=B4`（现有 `SW5` 那条保持不动） |
| 2 | `design_top_wrapper.v` | 新增端口 `I_sw`、加 2 拍同步（异步输入）、送到 `hdmi_mixer` |
| 3 | `hdmi_mixer.v` | 新增 `I_page[1:0]`；**只在文字行区域块内**把 `I_xxx` 数据源换成 `case(I_page)` 选出的值；框与状态条不动 |
| 4 | `tools/verify_osd_layout.py` | **不需要改**（区域数与坐标都没变） |

### 3.1 关键实现纪律

1. **页选是低频信号，但仍要同步**：拨码是异步机械输入，直接进 HDMI 域的组合链
   会引入亚稳态风险 ⇒ 2 拍同步后使用（与 `S_ae_auto_h` 同一套）。
2. **不新增区域、不新增字模查表实例**：`osd_char_lib` 全模块**只有一个实例**，
   `S_pf_char/S_pf_row` 只能由那个唯一的 always 块驱动（这是 P6 踩过的坑：
   两个 always 块驱动同一组信号在 ModelSim 里不报、综合必报多驱动）。
3. **数据源替换点必须在"槽位→字符码"之前**：即在算 `hexdig(...)` 之前换数据，
   而不是在最终颜色 mux 里换 —— 后者会让九路区域各自带一份 mux，反而增面积。
4. **页面切换不需要任何跨域握手**：拨码是准静态电平。

## 4. 验收（P8-b 完成的判据）

| 层 | 判据 |
|---|---|
| L1 | 新增 `tb_osd_page`：4 个 `I_page` 取值下，逐页比对"文字行的槽位→字符码"输出与 Python 独立模型一致 |
| L2 | `verify_osd_layout.py` 仍报 **9 个区域、无重叠**（证明没新增区域） |
| L2 | `verify_pin_assign.py` 退出 0（新增 SW1/SW2 引脚无重复、无冲突） |
| L3 | 构建零违例；**`check_crit_path.py` 复查关键路径没有从 HDMI 域变得更差** |
| L4 | 拨 SW1/SW2 四档，屏幕文字行按 §2 表格切换；**框与状态条在所有档位都正常** |

### 4.1 交付时**必须同时给出**的反面证据

- **面积没有明显增长**（对照本版 slice 75.74%）—— 若增长 >1 个点，说明实现方式错了（见 §3.1 第 3 条）；
- **关键路径没有变差**（对照本版 SWNS +0.140 ns / HDMI 12.931 ns）。

> 这两条是 P8-b 的**立论基础**：它之所以被选中，就是因为"面积与时序代价近乎为零"。
> 如果实测这两条不成立，**P8-b 的前提就垮了**，应该退回 P8-a 或重新设计。

## 5. 风险与诚实边界

| 风险 | 说明 |
|---|---|
| 拨码开关电平极性未知 | 需上板确认"拨到哪边是 1"。**不假设**，实现时留一个 `SW_ACTIVE_LOW` 参数，首次上板用页 0/3 对照确定 |
| 4 个开关可能不是全部可用 | 引脚表说"空闲"，但板上是否有上拉/下拉、是否被其它功能复用**未核实** ⇒ 首次上板先只验 SW1/SW2 |
| 页 2 的 FIFO/MIPI 计数**目前不存在** | G1/G2 是**待实现的计数器**，不是现成信号。页 2 要真正可用，得先补这两个计数器（本身是遗留项，不是 P8 引入的） |
| SPI-Flash 固化 | **与本页设计正交**，是另一件事（把位流写进配置 Flash 使上电自加载），需要单独的步骤与验证，不在本设计范围内 |

## 7. G1/G2 实测钩子点（2026-09-27 查证，下一步照此执行）

### 7.1 G2 —— **性质与原记录不同：那是"从未例化的死代码"，不是"接错线"**

| 事实 | 位置 |
|---|---|
| `mipi_rx_error_detect.v` **在整棵树里从未被例化**（全工程搜索只命中它自己的 `module` 行） | `mipi_rx_error_detect.v:3` |
| 它的消费者把输入**硬接 0**：`.I_mipi_rx_error ( 1'b0 )` | `design_top_wrapper.v:1066`（`video_in u_video_in` 实例内） |

⇒ **G2 不是"某个信号接错"，而是"一个现成的错误检测模块躺在树里没人用"。**
修法 = 例化它 + 把输出接到 `u_video_in.I_mipi_rx_error`。

它的端口（已读源码）：`I_clk / I_rst_n / I_frame_start / I_frame_end / I_data_valid → O_mipi_rx_error`，
内部逻辑是**逐行列计数**、行长不对就置错（`S_line_cnt/S_col_cnt` + `S_line_end = ~I_data_valid & S_data_valid_1d`）。

**⚠ 三条必须先核清的（铁律四：上游语义不能想当然）**：
1. 它该挂哪个时钟域？候选 `S_csi_rx_clk`（`u_video_in` 就在这个域收数据）；
2. `I_frame_start/I_frame_end` 的**期望语义**（高有效脉冲？电平？）必须对着它第 26~60 行逐行读，
   不能拿 `S_ISP_O_tuser` 直接塞 —— P5 就是在这里栽的（`tvalid && tuser` 永不成立）；
3. 它输出的错误是**电平还是脉冲**、以及 `u_video_in` 期待哪种（接错会导致视频永久卡住而不是报错）。

### 7.2 G1 —— `w155_d512_fifo` 的 full 标志

| 事实 | 位置 |
|---|---|
| FIFO 例化点 | `mc_to_user_interface.v:70` — `w155_d512_fifo U_w155_d512_fifo( ... )` |

**下一步要做的两件事**：
1. 读该实例的端口表，确认 full 标志的**准确端口名与极性**（不要假设叫 `full_flag`）；
2. 若它没有引出到模块端口，则需在 `mc_to_user_interface.v` 上加一个输出（**注意：该模块有一定概率是厂家代码，加端口前先确认它在 `_Runs` 的 `.prj` 里的归属**）。

计数本身很简单（在目标域里一个饱和计数器，full 每帧上升沿 +1）；
**真正要小心的是跨域**：若 full 在 DDR 域（`S_ddr_clk`）而显示在 HDMI 域，
需要走与 P5/P6/P7 同一套"翻转标志 + 2-FF + 边沿捕获"，不能直接连。

### 7.3 顺序（不可颠倒，理由见 §5）

```
① 核清 7.1 的三条语义  →  ② 例化 mipi_rx_error_detect 并接上  →  ③ 做 G1 的 full 计数
→  ④ 跨域（若需要）→ ⑤ 再做 §3 的页选 mux（此时页 2 才有真实数据源）
```

**在 ②③ 完成之前不要做 ⑤** —— 否则会得到一个永远显示 `0000` 的"自检页"，
它比没有自检页更坏：会让人以为"检查过了、没问题"。

## 8. ★ 资料查证结果（2026-09-27，含一个反面结论）

### 8.1 反面结论：**厂家参考设计里也没有用过 `mipi_rx_error_detect`**

我原本打算"找到参考设计的原始接法来确认 §7.1 那三条语义，而不是靠读代码猜"。
在 `rtl_vendor/anlogic_example/` 下的全部例程（`lab_ex1_mipi_hdmi`、`lab_ex2_edge`、
`lab_ex3_osd`、`lab_topic2_basic`）以及 `lab_topic2_basic1.0` 里逐个搜索：

**`mipi_rx_error_detect` 在每个副本中都只命中它自己的 `module` 声明行 —— 从未被例化。**

⇒ **它在厂家发布时就是没人用的死代码，没有任何既有用法可以对照。**
这件事有两个后果：
1. §7.1 那三条语义**只能靠读它自己的源码推出**，没有捷径；
2. **反过来说，风险比原估计更高**：一个从未被集成、从未被验证过的模块，
   它的"期望输入时序"只有作者知道。**在我们的工程里首次启用它，等于首次验证它。**
   ⇒ 必须给它单独的 L1 测试（喂正确/错误行长的激励，看它是否按预期置错），
   **不能只靠"接上试试"** —— 因为接错的典型后果是视频永久卡住，而不是报错。

### 8.2 G1 钩子点查实（比原记录更明确）

`w155_d512_fifo` 的真实端口表（读自 `user_source/ip_source/w155_d512_fifo/w155_d512_fifo.v`）：

| 端口 | 说明 |
|---|---|
| `full_flag` | **真满**（深 512） |
| `afull` | **将满**，阈值由 `AL_FULL_NUM(500)` 决定 |
| `empty_flag` / `aempty` | 空 / 将空 |
| `wrusedw[8:0]` / `rdusedw[8:0]` | 写/读水位 |

而 `mc_to_user_interface.v:70~85` 的实例接法：

| 端口 | 现状 |
|---|---|
| `.afull ( S_fifio_pro_full )` | ✅ **已接** —— 反压用的是"将满" |
| **`.full_flag ( )`** | ❌ **悬空** ← **G1 的开口就在这里（第 77 行）** |
| `.wrusedw ( )` / `.rdusedw ( )` | ❌ 悬空 |
| `.empty_flag ( S_fifo_empty )` | ✅ 已接 |

**★ 这个指标的意义（比我原来记的更硬）**：
FIFO 深 512、`afull` 在 **500** 断言 ⇒ 设计留了 **12 格余量**给写方停手的时间。
**`full_flag` 一旦断言，就意味着那 12 格余量的反压失效了**（写方没停住，数据即将丢）。
⇒ 它不是"可选装饰"，而是**唯一能证明反压真正有效的证据**。

### 8.3 由此确定的两条实现纪律

1. **G2 必须配 L1 测试**（理由见 8.1）：构造"正确行长"与"错误行长"两种激励，
   断言 `O_mipi_rx_error` 的行为符合它源码的定义，**再接到 `u_video_in`**。
2. **G1 的计数要跨域**：该 FIFO 的 `clk` 是 `I_clk`（`u_mc_to_user_interface` 所在域，
   大概率是 `S_ddr_clk`），而显示在 HDMI 域 ⇒ 走 P5/P6/P7 同一套
   "翻转标志 + 2-FF + 边沿捕获"，**不能直连**。

> 注：`full_flag` 是**电平**不是脉冲。计数应取**上升沿**（每帧最多计一次），
> 否则持续满会把计数刷爆，反而失去"是否发生过"的语义。
