## 2. 硬件连接清单

| 接口 | 板上的位置 | 说明 |
|---|---|---|
| **电源** | DC 供电口 | 上电后确认电源指示灯亮；若板上有电源开关，拨到 ON |
| **HDMI 显示器** | HDMI OUT | 用显示器确认；不要用转接线（转接器常导致 TMDS 无法锁定） |
| **SC500CS 摄像头** | MIPI_CSI 排线座 | **注意排线方向与卡扣锁紧**；这是最常见的失效点 |
| **下载器（JTAG）** | JTAG 排针 | Anlogic 下载器；TD IDE 里需能识别到器件 |
| **按键** | 板载 KEY1–KEY4 | 本设计用了 **KEY1 / KEY2** |

**板上按键与 FPGA 引脚（依据引脚分配表 §十三）**：

| 按键 | FPGA 引脚 | 本设计用途 |
|---|---|---|
| **KEY1** | **D5** | 短按 → 切换边缘检测；长按 → AE 调节 |
| **KEY2** | **A9** | 短按 → 切换 OSD 开关；长按 → AE 调节 |
| KEY3 | B9 | 未用（备用） |
| KEY4 | C7 | 未用（备用） |

> `pin.adc` 已在 2026-09-18 修正：原本复用的 `N2` / `J14` 是 **DC3 扩展排针（GPIOA_19 / GPIOB_12）**，
> 板上没有按键接在那里 —— 悬空靠 `PULLUP` 读到恒 `1`，**短按永远不会发生**，
> `mode[1:0]` 永远是 `2'b00`，新功能会完全失效。现已改为 `D5` / `A9`。
> 依据：`doc/analysis/_extract/DX_HX1P35B引脚分配汇总.txt` L131–136。

| 操作 | 期望现象 |
|---|---|
| 同时打开 OSD（KEY2）且 `mode[1:0] = 2'b11` | 若 Logo 区域与模式数字区域**重叠**，应看到 **Logo 盖住数字**（优先级正确） |

| 操作 | 期望现象 |
|---|---|
| **长按 KEY1**（≥ 500 ms 保持不放） | **模式不变**（边缘检测不切换）；画面**亮度逐渐变化**（AE/AG 自动调节步进） |

> 依据：`risks.md` R-07 第 3 点（`rc_ae_tick >= 99999` @23.81 MHz ≈ 4.2 ms，×32 ≈ 134 ms/步）。

### 6.1 待核实的疑点：`I_rst_n` 的引脚分配

`pin.adc` 里 `I_rst_n = R10`，但：

- 引脚分配表的 **§二（4 组 LED）/ §十二（乒乓开关）/ §十三（4 组按键）** 里 **都没有 R10**；
- 引脚分配表的 **§十五（以太网）** 里 **`TXEN = R10`**。

⇒ **`I_rst_n` 很可能被分配到了一个以太网引脚上，而板上没有对应的复位按键。**
（本设计不使用以太网，所以大概率不会造成功能冲突；且写了 `PULLUP`，会读到恒 `1` = 复位释放。）

**这意味着：板上很可能没有可用的复位按键，`I_rst_n` 实际上是常 `1`（不复位）。**

- **影响**：上电配置完成后**不能手动复位**；若出现死锁只能重新下载 bitstream。
- **这是 lab1 沿用下来的分配，不是本次改动引入的。**
- **建议**：上板时确认 R10 上是否有按键。若需要真正的复位键，把 `I_rst_n` 改到
  **KEY3 = B9** 或 **KEY4 = C7**（这两个是确认存在的板载按键）。

> 依据：`DX_HX1P35B引脚分配汇总.txt` §十三（L131–136）、§十五（L144–154）。

### 缺口 A：`settings.cfg` 从未定义 `sp` ⇒ **P&R 阶段从不重读 `pin.adc` 与 `.sdc`**

`F:\al\scripts\DefaultFlow.tcl` 第 80 行：

```tcl
if { [info exists sp] } {
  if { [info exists ADCList] } { foreach adc $ADCList { read_adc $adc } }
  if { [info exists SDCList] } { clear_sdc -user; foreach sdc $SDCList { read_sdc $sdc } }
}
```

- **lab1 / lab2 / lab3 / lab4 的 `syn_1` 与 `phy_1` 的 `settings.cfg` 全都没有 `set sp`**（已逐一核对）。
- ⇒ 引脚与时钟约束**只在综合第一段（`read_design`）读一次**，之后全部来自网表里内嵌的那一份。
- ⇒ **P&R 阶段对 `pin.adc` / `.sdc` 的任何修改都不会生效。**
- 实证：修改 SDC 后重跑 P&R，WNS **分毫不变**（仍 −111 ps），且 P&R 日志里**完全没有 SDC 行**，
  反而出现 `USR-6001 WARNING: No clocks matched ...`。
- **修法**：在 **`phy_1/settings.cfg`** 中加 `set sp 1`（本次已加）。加完后日志出现
  `read_adc ../../../user_source/constraints_source/pin.adc` 与 `read_sdc ../../camera_to_dsi_display.sdc`。

> ### ⚠⚠ 重要边界：`set sp 1` **只能加在 `phy_1`，绝不能加在 `syn_1`**
>
> 本次实测踩到并纠正：
>
> | 加在哪 | 结果 |
> |---|---|
> | **`phy_1/settings.cfg`** | ✅ **正确**。P&R 段的 `prepare` 是**先 import 网表、再读约束**，顺序正确 |
> | **`syn_1/settings.cfg`** | ❌ **会直接失败**。综合第一步 `read_design` 是**先 prepare 再 elaborate**，读约束时还没有网表模型，于是报：<br>`USR-8128 CRITICAL-WARNING: Please import a work model first.`<br>并产生 `.read_design.error.f`，整段 **2.5 秒**即中止（正常需 21 秒） |
>
> ⇒ **综合不需要 `sp`** —— 它由 `read_design_fun` 自己读 ADC/SDC（`DefaultFlow.tcl:101` 与 `:109`）；
> **只有 P&R 需要 `sp`** 来触发重读。

### 缺口 B：`.sdc` 把 `pll_clk_24m` 与 `HDMI_PIXEL_CLK` 归为**同一同步组**

```tcl
set_clock_groups -asynchronous \
    -group {mipi_rx_ck_pad MIPI_RX_BYTE_CLK} \
    -group {sys_clk_50m pll_clk_100m pll_clk_24m HDMI_PIXEL_CLK HDMI_SERIAL_CLK} \   # <- 同一组 = 互相同步
    -group {...ddr_clk ...usr_clk}
```

- 两者是 PLL 的两路独立输出（`clkc[1]` 23.810 MHz / `clkc[4]` 75.002 MHz）。
- lab1–lab3 无碍，因为**没有逻辑跨这两域**；lab4 新增的 `key_mode_ctrl` 把 `mode[1:0]`
  经 2-FF 同步器送入 HDMI 域，于是产生了 `pll_clk_24m -> HDMI_PIXEL_CLK` 检查组。
- **失败形态极易误判为"关键路径太慢"，实际是约束问题**：

  ```
  Path Group     : pll_clk_24m -> HDMI_PIXEL_CLK
  Slack          : -0.111 ns        (另 1 条 -0.027 ns，共 2 Viol Endpoints / 3 Total)
  Logic Level    : 0                <- 零级逻辑！
  Data Path Delay: 0.529 ns         (cell 0.224 + net 0.305)
  Budget         : 0.653 ns         <- { HDMI_PIXEL_CLK rising@546.653 - pll_clk_24m rising@546.000 }
  ```

  STA 拿两个**无固定相位关系**的 PLL 输出抽头去比较边沿，挑中了一对只差 0.653 ns 的，
  而数据路径本身就有 0.529 ns。**逻辑级数 0 却违例**，就是"这是约束问题"的铁证。
- **修法**：在 `.sdc` 末尾加一条最小范围的 false path（本次已加，纯 ASCII）：
  ```tcl
  set_false_path -from [get_clocks {pll_clk_24m}] -to [get_clocks {HDMI_PIXEL_CLK}]
  ```
  它**只**关掉这一条跨域检查，不影响任何同域路径
  （`pll_clk_24m→pll_clk_24m`、`HDMI_PIXEL_CLK→HDMI_PIXEL_CLK`、`HDMI_PIXEL_CLK→HDMI_SERIAL_CLK` 仍全部分析）。
- **修复效果**：Setup WNS 由 **−111 ps / 2 FEPs → +115 ps / 0 FEPs**；全部 path group 0 违规。

### 缺口 A 的一个额外含义（比 B 更要紧）

既然**原厂模板下 P&R 不重读 `pin.adc`**，那么"改了引脚就上板"是**不成立的** ——
必须重新综合（`read_design` 段会读 `pin.adc`）才能让引脚改动进入网表。
本次 `I_button` 从 `N2/J14` 改到 `D5/A9` 能真正生效，正是因为重跑了 `read_design → opt_rtl → opt_gate`。
