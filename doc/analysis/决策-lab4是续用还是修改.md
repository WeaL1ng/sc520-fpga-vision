# 决策：lab_ex4 是直接续用还是继续修改

> 日期：2026-09-20
> 问题：`rtl_vendor/anlogic_example/lab_ex4_all_features_SC500_720P` 按照步骤方案，
> 是**直接续用**，还是**继续修改**？
> 结论依据：赛题指南原文 + Q&A 原文 + 两个工程的实测数据

---

## 0. 结论

### **继续修改，但改动范围很小 —— 只需替换图像处理算法模块。**

lab_ex4 **不能原样提交**，但**不需要推倒重来**。
它已经满足 4 项基础要求中的 3 项，唯一的问题是第 (2) 项踩了赛题的一条硬规则。

**并且：`lab_topic2_basic` 不要作为主线**（它的输出分辨率只有 1024×600，是 Q&A 允许的最低值，
没有余量；且它缺 OSD 之外的差异化优势）。

---

## 1. 决定性的证据链

### 1.1 赛题对图像处理算法有一条**硬性差异要求**

`2026选题指南（康芯）` 第 170–176 行，**选题二 基础要求**：

```
（1）实现视频采集与显示功能：使用 MIPI 摄像头采集视频数据，并通过 HDMI 接口实现视频实时输出显示；
（2）实现基础图像处理功能：在 FPGA 端完成至少一种图像处理算法（如边缘检测、灰度变换或二值化等），
     并输出处理后视频；
（3）实现图像处理结果显示：处理后的视频需稳定输出至 HDMI 显示设备，画面连续，无明显异常；
（4）实现信息叠加功能：在输出视频画面中叠加简单图形或文字信息（OSD），并包含"安路"标识Logo。
注：基础要求重点考察系统完整性与稳定性，算法复杂度不作强制要求。
每个基础要求会有参考实例提供，但提交的参赛作品中图像处理算法不能和参考实例相同。   ← ★ 关键
```

### 1.2 参考实例 `lab_ex_2` 用的正是**边缘检测**

同一文档第 137–138 行，官方提供的三个例程：

```
lab_ex_1  使用 MIPI 摄像头实现图像采集，存储至片内集成 DDR 中，并通过 HDMI 接口驱动显示屏，
          实现原始图像实时显示。
lab_ex_2  使用 MIPI 摄像头实现图像采集，对采集到的图像进行边缘检测算法处理，存储至片内集成 DDR 中，
          并通过 HDMI 接口驱动显示屏，实现边缘检测图像实时显示。      ← ★ 参考实例 = 边缘检测
lab_ex_3  使用 MIPI 摄像头实现图像采集，存储到片内集成 DDR 中，并通过 HDMI 接口驱动显示屏，
          在实时显示的图像上叠加了安路 Logo 与运行计数器，实现带叠加信息的图像实时显示。
```

### 1.3 lab_ex4 目前用的就是 **Sobel 边缘检测**

| 证据 | 内容 |
|---|---|
| `.al` 编译列表含 | `isp/edge_detect_96.v` |
| `isp_top.v` 例化 | `edge_detect_96 #(.IMG_WIDTH(1280), .IMG_HEIGHT(720), .EDGE_TH(11'd80))` |
| 功能 | Sobel 卷积（`EDGE_TH` 阈值 → 二值边缘图） |

⇒ **与参考实例 `lab_ex_2` 算法相同 ⇒ 违反"图像处理算法不能和参考实例相同"。**

### 1.4 另外一个约束：输出分辨率不能低于 1024×600

Q&A 原文（`DX_2026安路赛题一、二相关Q&A.txt`）：

```
Q：赛题一、二显示器有什么要求？
A：赛题一的显示器需要支持音视频输入或者有外接音箱，赛题二的显示器建议分辨率 720p 以上，
   不能低于 1024*600。
```

实测两个工程的输出：

| 工程 | `uivtc` 实际参数 | 分辨率 |
|---|---|---|
| **lab_ex4** | `H_ActiveSize=1280, V_ActiveSize=720` | **1280×720（720p）** ✅ |
| lab_topic2_basic | `H_ActiveSize=1024, V_ActiveSize=600` | **1024×600** ⚠ 恰好等于允许的最低值 |

⇒ lab_topic2_basic 的分辨率**贴着红线**，没有任何余量；
而赛题 2.5 自备设备建议是 **1280×720@60Hz**。

## 2. lab_ex4 对 4 项基础要求的实际满足情况

| 要求 | lab_ex4 现状 | 判定 |
|---|---|---|
| **(1)** MIPI 采集 + HDMI 实时显示 | lab1 完整通路：SC500 → MIPI 2lane 解包 → ISP → DDR 帧缓存 → HDMI | ✅ **满足** |
| **(2)** FPGA 端图像处理，且**算法不能同参考实例** | Sobel 边缘检测 —— 功能上满足，**但算法与 `lab_ex_2` 相同** | ❌ **不满足** |
| **(3)** 处理后视频稳定输出 | Setup WNS **+110 ps** / Hold **+20 ps** / 0 违例（09-20 10:41 实测） | ✅ **满足** |
| **(4)** OSD 叠加含"安路"Logo | `hdmi_mixer.v`：160×160 安路 Logo（`LOGO_X/Y=0, LOGO_W/H=160`，蓝 `24'h1f315c` + 红 `24'hfec1c2d`）+ `osd_char_lib` 动态文字 | ✅ **满足** |

⇒ **4 项里 3 项已满足，只有第 (2) 项的"算法差异"不合规。**
⇒ 改动范围 = **替换一个模块**，不动采集、缓存、显示、OSD、按键框架。

## 3. 两个方案的对比（决定为什么选 lab_ex4 为主线）

| 项 | **lab_ex4_all_features** | lab_topic2_basic |
|---|---|---|
| 图像算法 | Sobel 边缘检测 | 灰度 / 二值化 / 反色 |
| 与参考实例 `lab_ex_2` 是否相同 | ★ **相同（违规风险）** | 不同（合规） |
| **输出分辨率** | **1280×720（720p）** ✅ | **1024×600**（允许的最低值）⚠ |
| OSD 含安路 Logo | ✅ 有 | ✅ 有 |
| 按键控制图像算法 | ✅ 有（KEY1） | ✅ 有（KEY1 切 4 模式） |
| Slice 占用 | 15,446 / 21,216 = **72.80%** | 14,999 / 21,216 = **70.70%** |
| Setup WNS | **+110 ps** | +101 ps |
| Hold WNS | +20 ps | +20 ps |
| DSP | **9 / 40** ✅ 省 | 21 / 40 |
| ERAM | 40 / 108 | 31 / 108 |
| 已知遗留问题 | `I_rst_n` 引脚疑点、AWB 未重构、既有缺陷 A1/A2/A3 | AG 上调仅 9 步、裕量薄 |

### 选 lab_ex4 的理由（按重要性）

1. **分辨率合规且有升级空间**：720p vs 1024×600。lab_topic2 已经在红线上。
2. **DSP 只用了 9/40**：lab_topic2 的灰度模块吃掉了 12 个 DSP（4 像素×3 乘法）。
   选 lab_ex4 意味着**还有 31 个 DSP 可用于后续算法升级**。
3. **改动面最小**：lab_ex4 的 OSD、按键长短按、跨域同步都已实测收敛；
   只需换掉 `edge_detect_96`。
4. **lab_topic2_basic 可以当"备选算法来源"**，不必丢弃 —— 它的
   `gray_binary_96.v` 已验证正确（我做过 30 项自检仿真全通过），
   可作为新算法的一部分或对照。

## 4. 具体要改什么（如果决定继续 lab_ex4）

### 4.1 必做（合规性，否则不能提交）

| # | 改动 | 说明 |
|---|---|---|
| **A1** | **替换 `isp/edge_detect_96.v` 的图像处理算法**，使其**不等于** Sobel 边缘检测 | 赛题 2.3 注 |
| **A2** | 保留/演示一个"**升级前为参考例程、升级后为自主算法**"的对比能力 | 加分且证明不是抄例程 |
| **A3** | 文档里明确写出算法与 `lab_ex_2` 的差异点 | 评审会看 |

### 4.2 推荐的新算法方向（满足"与边缘检测不同"且工作量可控）

| 方向 | 与参考实例的差异 | 资源代价 | 我的评估 |
|---|---|---|---|
| **灰度 + 二值化 + 自适应阈值**（把 lab_topic2 的 `gray_binary_96` 移植进来，再加局部阈值） | 完全不同 | 12 DSP（有 31 个余量） | **最省事，已验证** |
| **画面卡通化**（边缘提取 + 区域填充/双边滤波 + 颜色量化） | 完全不同，且命中**扩展要求 (1)** | 中高 | 收益最大，但工作量大 |
| **反色 / 伪彩色映射 / Gamma 校正 / 直方图均衡** | 完全不同 | 低 | 工程量小，但可能被认为"太简单"（不过赛题明说"算法复杂度不作强制要求"） |
| **目标检测（几何形状识别）** | 完全不同，且命中**扩展要求 (2)** | 高 | 冲奖用 |

> 注：赛题原文 **"算法复杂度不作强制要求"**，且 **"重点考察系统完整性与稳定性"**。
> 所以**不建议为了炫技而牺牲时序裕量** —— lab_ex4 的 slice 已占 72.80%。

### 4.3 建议同时处理（非合规必需，但影响稳定性/评分）

| # | 项 | 依据 |
|---|---|---|
| B1 | **`I_rst_n` 引脚疑点**：现在分配到 `R10`，而引脚表里 `R10 = 以太网 TXEN`，§二/§十二/§十三都没有它 ⇒ 板上很可能**没有可用复位键** | `上板测试-操作手册.md` §6.1 |
| B2 | **既有缺陷 A1/A2/A3**（DDR 写优先 mux 无仲裁、`uial2axis` 帧内不自恢复、`I_mipi_rx_error` 硬接 0） | `risks.md` R-04（上板长时间运行是基础要求 (3) 的验收点） |
| B3 | **AWB 重构**（P1a）：合并两个 `divider`，约省 750 LUT，给新算法腾空间 | `P1a-AWB重构设计.md` |
| B4 | 上板连续运行 ≥10 分钟验证无撕裂/死锁 | 指南 2.3(3) |

## 5. 风险提示

| 风险 | 说明 |
|---|---|
| **"算法不同"的判定尺度不明** | 赛题只说"不能和参考实例相同"，未定义"相同"的程度。稳妥做法：**算法原理层面就不同**（如灰度/二值化 vs 卷积边缘），而不是"改个阈值算不算不同"。 |
| **换算法后时序可能变差** | lab_ex4 当前 72.80% slice、Setup 仅 +110 ps。新算法若比 Sobel 更重，需要重新评估。好消息是 **DSP 只用了 9/40**，优先用 DSP 实现。 |
| **lab_topic2_basic 的坑不要带过来** | 它的 `ae_set` AG 上调仅 9 步（初值 80、上限 89）——见 `lab_topic2_basic-分析与测试报告.md` §6.1。lab_ex4 用的是 `key_mode_ctrl` + 同款 `ae_set`，**这个坑可能存在**，上板前要确认。 |

## 6. 一句话回答

> **不要直接续用，要改，但只需替换图像处理算法这一个模块。**
>
> 依据：赛题 2.3 注明"提交作品中的图像处理算法不能和参考实例相同"，
> 而参考实例 `lab_ex_2` 就是边缘检测，lab_ex4 恰好用的也是 Sobel 边缘检测。
> 其余 3 项基础要求（采集显示、稳定输出、含安路 Logo 的 OSD）lab_ex4 **已经满足并实测收敛**。
>
> 同时**不要改用 `lab_topic2_basic` 作主线** —— 它的输出是 1024×600，
> 正好压在 Q&A 允许的最低值上，而 lab_ex4 是 720p。
