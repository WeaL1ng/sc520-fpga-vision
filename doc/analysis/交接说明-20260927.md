| 区域 | 坐标 | 内容 |
|---|---|---|
| LOGO | (7,34) | 安路 Logo |

## 4. 硬约束与教训（违反过的都标了代价）

### 4.1 四条铁律（工程原有）

1. **分时复用改造必须吞吐与资源同时验收**（4.34 拍/字、FIFO drop 0）
2. **改 RTL 前必须把"现状"与 RTL 逐行核对**（但见 §4.3 的补充）
3. **常量乘法绝不能用 DSP**（全用移位加法；`verify_td_reports.py` 断言 `dsp=0`）
4. **上游模块的 `tuser`/`tlast` 语义必须逐一核对**，不能想当然
   （`awb.v`：`O_tuser` 组合直通、`O_tvalid` 流水延迟 ⇒ `tvalid && tuser` **永不成立**）

### 4.2 本轮新增的三条

5. **新模块必须登记进 TD 工程**（`.al` + `syn_1/*.prj` + `phy_1/*.prj`，且要补**完整 `<File>` 块**）。
   只写 RTL 忘登记 ⇒ `HDL-8007 black box`，构建 6 秒就挂；只插一行 `<File Path=...>` ⇒ `PRJ-8601`。
6. **"逐行核对"不等于"它能工作"**。本轮真 bug：`case` 项写成 `4'd16`，**16 在 4 位里放不下 ⇒ 截断成 0**
   ⇒ 7 个赋值全成死代码、槽 16~22 落 `default` 空。我核对了 `AEINFO_W`、字模、多驱动、区域判断，
   **全对，但看的是"值"不是"位宽"**。⇒ **case 项的位宽必须与 case 表达式一致**。
7. **握手机制要能超时**：`w_committed = (回读 == 目标)` 这种"相等才继续"的设计，
   只要提交路径有一处不忠实（钳位/下溢/I2C 未返回/传感器拒收）就会**静默冻结**，
   症状只是"数值不再变化"，极难定位。

### 4.3 方法论（比具体 bug 值钱）

1. **诊断能力不足时改判据 = 猜**。P5 的颜色判据连改三轮（`CR_MIN` 160→146、加 `CB_MIN`、加比值判据）
   全因拿推测值调参；最后只加了一个"探测点自动锁定"的**观测量**，一次就拿到决定性数据
   （臂章 Cb=120 / 手掌 W=0）并得出**"不要动"**这个有依据的结论。
2. **证据不足时，正确动作是"再加一个能判定的观测量"，不是"再想想"**。
   本轮我误读诊断位、推出一个**子虚乌有的"握手死锁"**并写进报告；
   唯一可靠的一步就是"把 `clip` 接到 OSD"——**正是它推翻了我自己的结论**。
3. **凡拿诊断位当证据，必须回去读它的表达式**。写代码的人最容易误读自己信号的语义
   （`O_sat[1] = (AE到顶) || (AG到顶)`，我当成了"AG 到顶"）。
4. **"按访问顺序推最小存储量"必须同时核对读和写**。P7 只按"读"推 160 个背景槽，
   但一个槽一帧被 90 个块行**各写一次** ⇒ 变成垂直邻块比较 ⇒ 抗光照突变的保护**静默失效**。
5. **测试激励只覆盖一种结构 = 给某个设计打掩护**。P5 的 TB 总从帧第 0 拍开始 ⇒ 相位 bug 永不出现；
   P7 的场景背景全"垂直均匀" ⇒ "按列共享"恰好能工作。⇒ **新模块的 L1 必须包含真实结构场景**。
6. **不要拿过期报告当新结果**。`verify_td_reports.py` 读的是 `phy_1/*.area|timing`，
   若构建还没走到那一步，读到的是**上一轮的**。**判活看日志里有没有 `[syn] exit=` 行**。
7. **能复现旧行为的测试才有判别力**。只验"改了之后还是对"证明不了任何东西
   （`tools/check_tile_hit_th.py` 就是按这条做的：TH=12 在 0.5% 噪声下误报、TH=512 挡住）。

### 6.1 环境坑（都真实吃过亏）

1. **构建必须前台跑**：整轮 `syn 139~212s + phy 198~381s ≈ 500s`，**小于单次调用 600s 上限**。
   用后台作业时，**TD 子进程死了包装脚本会一直等**（作业状态仍显示"运行中"）⇒
   **判活只能看日志的最后写入时间**，不能看作业状态。
2. **`pwsh` 不在 PATH**（harness 里）⇒ 一律 `powershell -NoProfile -ExecutionPolicy Bypass -File`。
3. **PowerShell 没有 heredoc**；`python -c "..."` 里的引号会被吃掉 ⇒ **写 `.py` 文件再跑**。
4. **`.ps1` 的 BOM**：`edit` 工具会剥掉 UTF-8 BOM ⇒ PowerShell 5.1 按 GBK 读中文 ⇒ 解析失败。
   修复：`[System.IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($true)))`。
5. **ModelSim TB 陷阱**：中文名当 `[255:0]` task 实参会打成乱码（用 ASCII + `[511:0]`）；
   在 posedge 的 active 区读输出会读到 NBA 之前的值（加 `@(negedge clk)`）；
   `$value$plusargs` 放在第二个 `initial` 会与主块竞争（要在主块最前面读）。
6. **回退要逐字**：改坏了就 `Copy-Item` 从 release 目录覆盖回来，**再用 `Get-FileHash` 核对相等**。
   （用正则删代码会留下空白差异，哈希对不上。）
7. **沙箱**：本轮末尾 `windows-acl-run` 起不来（临时目录 `%TEMP%\dsh-*` 缺失）⇒
   **每条 `pwsh` 都要 `danger-full-access` 放行**。重启 DSH 或清 `%TEMP%` 大概率恢复。
   期间**用 `grep`/`read`/`write` 工具可以照常核对文件**，不受影响。

## 7. 诚实边界（不要当它们不存在）

1. **哑光橙与肤色在暗光下 Cb/Cr 重合**（各差 3 个 LSB）⇒ **任何矩形/线性判据都分不开**。
   当前选择"认哑光橙"，代价是**很暗的肤色可能误检**；反选则哑光橙认不出。**二者不可兼得**。
2. **`CB_MAX=115` 名存实亡**（臂章实测 Cb=120）⇒ 判据① 不参与检测，靠判据③。留着没错，但**要写明**。
3. **"自动锁定最暖像素"的探测点是离群点** ⇒ `C` 只适合量"占满画面的大块目标"；
   **`W` 才是可靠判据**。
4. **运动检测**：腐蚀零填充 ⇒ **画面最上/最左 8 像素带的运动报不出来**；只腐蚀不膨胀（框最多小 8 像素）；
   `O_blk_cnt` 是**块数不是目标数**；全局突变帧 `O_blk_cnt` 不为 0（抑制只由 `O_valid` 表达）。
5. **ERAM 读延迟已上板确认正确**（无 8 像素假带），这是 P7 唯一无法在仿真里验证的时序风险。
6. **运动检测未在真实视频下整定过**（只有合成图案 + 合成噪声）。
7. **`AE_AG_MAX=111` 的可接受性**基于本板实测（画面正常、检测正常）；**没有做长时间老化测试**。
