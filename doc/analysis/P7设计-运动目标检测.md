## 1. 判据（必须先定清楚，否则没法判"做完没有"）

| # | 判据 | 观测手段 |
|---|---|---|
| 1 | **挥手出框、静止无** | 上板：挥手 → 屏幕出现运动框 + 计数上升；手放下静止 2 秒 → 框消失、计数回 0 |
| 2 | 运动区域的**提示**（框）或**计数** | 满足其一即可；本设计**两个都给**（框 + 块数） |
| 3 | 零额外 DDR 带宽 | `doc/regression/trend.csv` 里用户口占用不上升（P1a 的事故就是带宽/FIFO 问题） |
| 4 | **光照变化不误报** | ⚠ **P6 之后 AE 会自动改亮度** ⇒ 判据必须包含"开灯/遮镜头过程中不出现满屏运动框" |
| 5 | 不压垮时序/面积 | L3：零违例、slice ≤ 80%、ISP 域余量仍为正 |

> ★ 第 4 条是本阶段**最容易漏掉**的一条。P6 之前"帧差法"只要对付静止光照；
> P6 之后 AE/AGC 会主动改变整体亮度，纯帧差会把整个画面判成运动。
> 这是"**先做 P6 再做 P7**"这条顺序安排的真正原因（见实施方案 §10）。

## 3. 亮度代理：为什么用 **G 通道** 而不是完整 Y

`luma_stats` 算的 `Y = (77R+150G+29B)>>8` 要 12 个移位加法（≈180 LUT）。
运动检测是**差分**运算 —— 只要"亮度代理"与真实亮度**单调一致**，差分结果就一致。

- G 占 Y 的 **58.6%**（150/256），是最强的单通道代理；
- 用 G 的代价是 **0**（不需要任何算术，直接切片）。

⇒ **本设计用 G**，并在注释与报告里写明这是刻意的近似（不是"算错了亮度"）。
⚠ 若将来要和 AE 的统计口径严格一致，可以改成复用 `luma_stats` 的输出（代价 +32 FF +1 拍延迟）。

## 4. ★★ 存储结构：三次权衡，存储量从 14,400 降到 160

### 4.1 原方案（实施方案 §"阶段 P7"）说什么

> 「缩略帧存 ERAM：14,400 × 8 bit = 115,200 bit ≈ 6 块 ERAM（存"上一帧"）」

即：把整帧的 160×90 = 14,400 个块的亮度存下来，下一帧逐块比对。

### 4.2 核对后的三个问题

| # | 问题 |
|---|---|
| ① | **14,400 个值的读-改-写需要双口/多次访问**：单口 ERAM 在同一拍既读旧值又写新值要拆成两拍，控制复杂度显著上升 |
| ② | **其实不需要存整帧** —— 见 4.3 |
| ③ | 若改用寄存器数组，读地址是"每块一个、顺序推进"，会退化成 **160:1 的读 mux**（15 bit × 160 ≈ 600 LUT，再加背景 8 bit × 160 ≈ 320 LUT）⇒ 近千 LUT，**比 ERAM 方案贵得多** |

### 4.3 ★ 关键观察：只需要 160 个值，而不是 14,400 个

块行（block row）是**按顺序**遍历的：帧内访问顺序恒为
`by = 0,1,2,…,89`，每个 by 内 `bxc = 0,1,…,159`。

块 `(by, bxc)` 在**第 N 帧**要比较的对象，是**第 N−1 帧同一个 `(by, bxc)`** 的背景值。
而第 N−1 帧的 `(by, bxc)` 早在"上一帧走到 by 这一行"时就被读过了，
之后**直到本帧再走到 by 之前，不会再被访问**。

⇒ 只要保留 **160 个"当前 by 行"的背景值**就够了：走到 `by` 时用它们、
同时用本帧的结果覆盖它们；等下一帧再走到 `by` 时拿到的正是上一帧的值。

```
  存储量：14400 × 8 bit  →  160 × 8 bit   （降 90 倍）
  ERAM  ：6 块            →  1 块（160×8；再给累加器 1 块 160×16）
```

**累加器同理**：一次只在一个块行里累加，也只需要 160 个（15 bit，见 §5.2）。
⇒ 总计 **2 块 ERAM**（108 块里现用 47 块，余量充足）。

> ★ 这条"**按访问顺序推最小存储量**"的思路，和 P5 的"增量求包围框、
> 不要 144×8 计数器阵列"是同一类简化：**先看访问模式，再决定存什么**。

## 5. 逐拍时序（本设计最容易写错的地方，先把数算清）

### 5.1 几何

```
每拍 4 像素（96 bit = 4×RGB888）
每行 1280/4 = 320 拍
块 = 8×8 像素 = 宽 8 像素 = 2 拍 / 块
块列数 = 1280/8 = 160        块行数 = 720/8 = 90
总块数 = 160×90 = 14,400
```

### 5.2 一个块的累加过程

| 项 | 值 |
|---|---|
| 一个块包含 | 8 行 × 2 拍 × 4 像素 = 64 像素 |
| 每拍 G 之和 | 最大 4×255 = 1020（10 bit） |
| 一个块的总和 | 最大 16×1020 = **16,320**（**15 bit**） |
| 块亮度 | `blk = sum >> 6`（除以 64 = 右移 6） ⇒ 0..255（8 bit） |

### 5.3 定稿时机：每 2 拍定稿一个块

块的累加在"块行的第 8 行 + 该块的**第 2 拍**"完成。
块 `bxc` 的第 2 拍 = 行内第 `2·bxc+1` 拍（**奇数**）。
⇒ **在每个奇数拍定稿一个块**，正好是"每 2 拍一次"，与访问节奏完美吻合。

### 5.4 ★ 一个漂亮的性质：最后一个块恰好在帧的最后一拍定稿

```
最后一行的行号 719 = 8×89 + 7  ⇒ 是块行 89 的第 8 行 ✓
该行最后一拍   319             ⇒ 是奇数 ✓ ⇒ 块 bxc = 159 在此定稿
⇒ 帧末不需要额外的"收尾状态机"：把帧边界定义在"最后一个块定稿"那一拍即可。
```

⇒ 这与 P5 的"帧末结算"是同一手法，但更干净（P5 还要额外判 tile 行末）。

### 5.5 单口 ERAM 的访问安排（每块 2 拍 = 一个完整的读-改-写周期）

| 拍 | 对累加器 RAM | 对背景 RAM |
|---|---|---|
| 偶数拍 `2k` | 发出读 `addr=k` | （若非定稿行）空闲 |
| 奇数拍 `2k+1` | 用读回值 + 本块 2 拍的 G 之和 ⇒ 写回 | ① 若 `line%8==7`：发读 `addr=k` 取背景 |

> ⚠ 定稿行（`line%8==7`）的第 3 次访问（背景的写回）要么再等一拍，要么
> 把背景 RAM 用**真双口**原语。⇒ **实现前必须先确认本工程可用的 ERAM 原语是
> 单口还是简单双口**（`logo_rom_eram.v` 是只读 ROM，不能直接照抄）。
> **这是动 RTL 前必须查清的一件事**（铁律二），见 §9 Step 0。

## 6. 判决、抗光照突变、去噪

### 6.1 sigma-delta 背景建模（而不是纯帧差）

```
diff = |cur − bg|
mot  = (diff > MOT_TH)                       // MOT_TH 初值 18（8 bit 域）
bg  <= (cur > bg) ? (bg + STEP) : ((cur < bg) ? (bg − STEP) : bg)   // 饱和
```

**为什么不用纯帧差**：帧差比较的是"相邻两帧"，AE 一改亮度，整帧差值都变大
⇒ 满屏误报。sigma-delta 让 `bg` **缓慢跟踪**场景，光照渐变被吸收掉，
只有"比背景更新快得多"的变化才判成运动。

### 6.2 ★ 全局光照突变抑制（P6 之后必需）

即使 sigma-delta，AE 一个台阶（比如曝光一次跳 256 ⇒ 亮度阶跃）也会让整帧
瞬间偏离背景。加一条**全局变化检测**：

```
本帧运动块数 > 全部块数的 GLOBAL_PCT%（默认 50%）
   ⇒ 本帧判为"全局光照突变"，O_valid = 0（不报运动）
   ⇒ 同时让 bg 用更大步长（或直接装载 cur）快速追上
```

> 代价：~40 LUT（一个计数器 + 一个比较 + 一个步长选择）。
> 收益：把"AE 一动就满屏框"这个**必然会发生**的失败模式直接消掉。

### 6.3 去噪：**2×2 腐蚀**（而不是 3×3 形态学）

原方案写"3×3 形态学（腐蚀→膨胀）去噪"。核对后的代价分析：

| 做法 | 代价 | 结论 |
|---|---|---|
| 3×3 形态学（腐蚀+膨胀） | 需要一个 160 bit 的行位图 × 3 行 = 480 bit 窗口，每块 9 输入 min/max ⇒ **~600 LUT**；且"右邻居"当拍不可得，要再延迟一个块 | ❌ 太贵 |
| **2×2 腐蚀**（本块 ∧ 左块 ∧ 上块 ∧ 左上块） | 一行 160 bit 的"上一块行"位图（160 FF）+ 1 bit 左邻居延迟 ⇒ **~170 LUT** | ✅ **选定** |
| 只加"最小块数"门限 | ~10 LUT | ✅ 同时保留（治"孤立斑点"） |

**2×2 腐蚀的效果**：单块孤立噪声被完全去掉；真实运动目标（几十个块）只
在**左上角各缩一个块（8 像素）**，而包围框本来就外扩到块边界（±8 像素）
⇒ 量级相同，不影响"框住目标"的展示目的。

**诚实标注**：本设计**只腐蚀、不膨胀**，因此框会比"理想的形态学方案"
略小一点（最多 8 像素）；且**不做连通域标记**，所以"计数"是**运动块数**，
**不是目标个数** —— 与 P5 的 `O_tile_cnt` 一样，必须在 OSD 上按真实含义标注。

### 6.4 包围框

对腐蚀后的运动块求 min/max `(bxc, by)`，再 `×8`（= 左移 3 位，零成本）得到像素坐标。
与 P5 相同：**外扩到块边界**，报告与 OSD 都不假装像素级精确。

## 7. 跨域与输出

与 P5/P6 **同一套**：帧末锁存整组结果 + 翻转 `O_tog` → 2-FF 同步 → 边沿捕获。

| 输出 | 位宽 | 用途 |
|---|---|---|
| `O_x_min/O_x_max[10:0]`、`O_y_min/O_y_max[9:0]` | 11+11+10+10 | 画运动框 |
| `O_blk_cnt[13:0]` | 14 | 运动块数（0..14400）—— **不是目标个数** |
| `O_valid` | 1 | 本帧是否有运动（含"全局突变"抑制后的结果） |
| `O_global_chg` | 1 | 本帧是否被判为全局光照突变（**诊断用，要上 OSD**） |
| `O_frame_start` | 1 | 帧结算单拍（跨域握手） |

**OSD 显示**：`M 0000,000 N 0000 G` 形态（十六进制优先，零比较链；`G` 亮起 = 本帧是全局突变）。
复用 P5 的目标框绘制逻辑（另起一个颜色，比如青色），与目标框并存。

**LED**（扩展(3) 已做）：`O_led[1]`/`O_led[2]` 已被 P5 的形状占用；
运动检测用 **`O_led[3]`（原为 AE 自动模式指示）**？—— 不，AE 模式指示有用，
⇒ P7 时把 LED 语义改成：`LED3 = 有运动`，`LED4 = AE 自动模式` 保留，
`LED2` 从"形状 BAR"改成"有目标 **或** 有运动"？**这属于要重新决定的接口**
（见 §9 Step 4），不能随手改 —— 扩展(3) 已经上板验证过 LED 语义。

## 10. 与实施方案原方案的差异（诚实记录）

| 原方案 | 本设计 | 原因 |
|---|---|---|
| 缩略帧存 ERAM：14,400×8 bit ≈ 6 块 ERAM | **160×8 bit（1 块 ERAM）** | §4.3：按访问顺序推，只需当前块行的背景值 |
| "8×8 块平均"（用亮度） | 用 **G 通道代理** | 差运算只需单调一致；省 ~180 LUT |
| 3×3 形态学（腐蚀→膨胀） | **2×2 腐蚀**（不膨胀） | §6.3：3×3 要 ~600 LUT 且要处理"右邻居不可得"；2×2 只要 ~170 LUT |
| 简单帧差 + sigma-delta 二选一 | **sigma-delta 为准 + 全局突变抑制** | §6.2：P6 之后 AE 会主动改亮度，纯帧差必然满屏误报 |
| 输出"包围框 + 计数" | 同上，但**明确计数是块数不是目标个数** | 与 P5 同样的诚实标注纪律 |
| 覆盖 进阶(4) + 扩展(3) | **扩展(3) 已单独先做完**（4 LED + 蜂鸣器，已构建） | 交替做"便宜且独立"的项，能更早拿到可上板的成果 |

§4.3 我写：
> "块行按顺序遍历 ⇒ 只要保留 160 个'当前 by 行'的背景值就够了：走到 by 时用它们、
> 同时用本帧的结果覆盖它们；等下一帧再走到 by 时拿到的正是上一帧的值。"

**"读"的这一半对，"写"的那一半错**：一个槽 `bg[bxc]` 在**一帧之内**会被
**90 个块行各写一次**。于是 `(by, bxc)` 读到的不是上一帧的 `(by,bxc)`，
而是**本帧 `(by−1,bxc)` 刚刚写进去的值** —— 它变成了
**垂直方向的邻块比较（空域）**，而不是帧间比较（时域）。

**根因**：我用"访问顺序"推出了存储量的下界，但**只检查了读、没检查写**。
`(by,bxc)` 需要两个下标才能确定"同一个块"，我却只用了 `bxc`。
**"按访问顺序推最小存储量"这个方法本身没错，错在我没有把"写"也一起纳入推导。**

### 11.2 实测后果（不是理论担忧，是量化失败）

| 场景 | 错误行为 | 后果 |
|---|---|---|
| B（160×160 块移动） | `raw=440`（应 400），框下边界多 **2 个块行"拖尾"** | 框偏大 |
| **C（整帧亮度阶跃 = AE 动一下）** | 只有前 **22 个块行**判成运动，`raw=3520`（24%） | **够不到 50% 全局门限 ⇒ `O_valid=1`** ⇒ **正是要求④"光照变化不误报"要防的失败模式** |

### 11.3 采用的修法（在"160 槽"这个约束下的正确解）

背景更新**只在 `by[2:0]==0` 的块行发生**（一帧 12 次）：
同帧内的拖动量 ≤ 12 < `MOT_TH`(18) ⇒ 整帧阶跃被完整判成 14400 块 ⇒ 全局抑制生效。

- 回退开关：`w_bg_we` 改回 `1'b1` 立刻复现 `raw=3520 / valid=1`（已写进 RTL 文件头）；
- 代价：背景自适应变慢（每列每帧 12 次更新，而不是设计意图的 90 次），
  亮度阶跃后约 2~3 帧吃回去。

### 11.4 ⚠ 残留限制（本版不做，如实记录）

**背景仍是"按列共享"的**：某列上下亮度差 > `MOT_TH`(18) 时该列会**长期报运动**。
根治必须按 `(by, bxc)` 存 **14400 × 8 bit ≈ 7 块 ERAM**，超出本节预算（≤2 ERAM）。
⇒ 这是"用块行共享背景换存储"这个设计的**固有代价**，不是可以靠调参消掉的。

### 11.5 ★ 这条要并入方法论

**"按访问顺序推最小存储量"必须同时核对读和写。**
只按读的访问模式推，会把"需要二维索引的量"错当成"一维就够了" ——
本次的后果是：**能通过的场景（块移动）看起来完全正常，而恰恰是"抗光照突变"这条
最关键的要求被悄悄破坏**（因为 24% < 50% 门限，抑制失效但没有报错，
只是那个开关不再起作用）。这类"看起来工作、关键保护静默失效"的错误最难发现。
