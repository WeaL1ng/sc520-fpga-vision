## 2. 改造方案：用 `gray_binary_96` 取代 Sobel

### 2.1 选型理由

| 候选 | 说明 | 取舍 |

2. **一次覆盖 3 种基础算法**（灰度变换、二值化、反色），远超"至少一种"的要求；
3. **已验证** —— lab_topic2 里已跑通并使用；
4. **零行缓冲** —— 纯逐像素处理，**只占 1 拍延迟**，对 awb 吞吐无影响

### 2.2 关键兼容性确认（这是能"直接替换"的依据）

`gray_binary_96.v` 第 4 行自己写着"接口与 `edge_detect_96` 完全兼容，可直接替换"。
逐项核对如下：

| 项 | `edge_detect_96` | `gray_binary_96` | 判定 |
|---|---|---|---|
| 端口集合 | clk/rst/tlast/tuser/tdata/tvalid/tready + O_* | 同 + `I_mode[1:0]` + `I_threshold[7:0]` | ✅ 超集 |
| 像素拆解 | `pix0=I_tdata[95:72]` … `pix3=I_tdata[23:0]` | `px0=[95:88]`(R)… `px3=[7:0]`(B) | ✅ **完全一致** |
| 96 bit 分组 | `{px3,px2,px1,px0}` | 同 | ✅ |
| 输出组结构 | 保持 4 像素/字 | 保持 4 像素/字 | ✅ |
| `O_tready` | 直通 | 直通 | ✅ |

> ⚠ 注意：`edge_detect_96` 的行缓冲会让输出**按 2 像素/拍**重排（`{out0,out0,out1,out1}`），
> 而 `gray_binary_96` 是 `{out0,out1,out2,out3}`。两者**字节分组边界相同**，
> 而下游 `data_96bit_to_128bit` 把每个 4 字节组当**不透明**处理
> （它只按 `S_cnt` 拼接字节流，不关心组内像素序）。
> 因此**像素在屏幕上出现的次序不变**，替换安全。

### 2.4 多比特跨时钟域处理（易错点）

原来只同步 **1 位**（边缘使能），现在要同步 **2 位模式号**，不能简单加宽就完事：
两位各自过 2 级触发器时到达时刻可能不同 ⇒ 可能**瞬间采到中间态**
（例：`01 → 10` 切换途中采到 `11` = 反色），在 CSI 域就是一个可见的错误画面。

**处理办法（两级防护，见 `design_top_wrapper.v`）：**

```verilog
S_mode_csi_s1 <= S_mode_24;          // ① 两位同组 2-FF 同步
S_mode_csi_s2 <= S_mode_csi_s1;
if (S_raw_tuser) S_mode_csi_r0 <= 2'b00;      // ② 帧首清零
else             S_mode_csi_r0 <= S_mode_csi_s2;   //   帧中跟踪
S_mode_csi_r1 <= S_mode_csi_r0;               //   帧首那一拍被锁住
```

- **帧首锁存** ⇒ 算法模式**不会在一帧中间变化**（否则该帧会半帧灰度半帧二值化）；
- `tuser` 是单比特、每帧一次的脉冲 ⇒ **多比特 CDC 最坏只影响那一帧**，
  绝不会把中间态持续带进数据通路。

代价：按键切换后**下一帧才生效**（1 帧 ≈ 16.7 ms，人眼不可察）。

> 极性注意：`isp_top` 内的 `awb`/`signal_delay` 用 `I_tuser` 作**高有效**帧首
> （`signal_delay.v:61/73`），本处用的 `S_raw_tuser` 正是 `isp_top.I_tuser` 的同一根线，
> 故用 `S_raw_tuser ? 0` 保持一致。

### 2.5 一个必须处理的副作用：OSD 使能

改造前 `O_mode[1]` 兼作 **OSD 使能**。改造后两位只表示模式号，
若继续用 `S_mode_hdmi[1]` 当 OSD 使能，则：

| 模式 | `S_mode_hdmi[1]` | 后果 |
|---|---|---|
| 0 原图 | 0 | ❌ **Logo 消失** |
| 1 灰度 | 0 | ❌ **Logo 消失** |
| 2 二值化 | 1 | Logo 显示 |
| 3 反色 | 1 | Logo 显示 |

⇒ **违反基础要求④（OSD 叠加含"安路"Logo）**。

**修正**：`.I_osd_en(1'b1)` —— **OSD 恒开**，Logo 在所有模式下都显示。
模式号仍通过 `.I_mode_disp(S_mode_hdmi)` 送到 OSD，屏幕上的模式数字与实际算法
**永远一致**（避免"显示灰度、实际二值化"这类现场难排查的错配）。

### 4.2 ⚠ 发现并修正：常量乘法占了 12 个 DSP

首版直接用了 lab_topic2 的原版 `gray_binary_96`，其中灰度加权和写作
`R*77 + G*150 + B*29`，综合器把 **12 个常量乘法**（4 像素 × 3 系数）
全部映射到 DSP ⇒ 全设计 DSP 从 8 涨到 **20（50%）**。

这与方案里的明确规定冲突（`赛题二-文件全量分析与方案建议.md` §0.5-L2 / 风险 R13）：

> **DSP 是真正稀缺的资源**（40 个），**常量乘法绝不能用 DSP** ——
> 4 px/拍 × 3 通道的常量系数一律用 CSD 移位-加法

**修正**：把三个系数改成移位加法（**严格等式，非近似**）：

```
77  = 1001101₂  = 64+8+4+1  ->  (r<<6)+(r<<3)+(r<<2)+r
150 = 10010110₂ = 128+16+4+2 ->  (g<<7)+(g<<4)+(g<<2)+(g<<1)
29  = 11101₂    = 32−2−1     ->  (b<<5)−(b<<1)−b
```

因为 77/150/29 的二进制逐位分解即为上式，所以对任意 8 位输入
**移位加法与原乘法逐位等价**（和位宽同为 16 位）。

> 注意：移位前必须先把 8 位输入扩展到 16 位，否则 `(r<<6)+(r<<3)` 会溢出 8 位。
>
> 修正后**重跑 58 项功能测试，仍 58/58 全过**，证明行为未变。

### 4.3 附带修正：模式切换按键改为循环

`key_mode_ctrl` 原本是"KEY0 翻 `O_mode[0]`、KEY1 翻 `O_mode[1]`"的**独立翻位**。
红线1 把 `mode[1:0]` 变成完整模式号后，独立翻位会导致：

| 当前 | 按 KEY0 | 按 KEY1 |
|---|---|---|
| 0 原图 | 1 灰度 | **2 二值化** |
| 1 灰度 | 0 原图 | **3 反色** |

⇒ **KEY0 永远只能在 原图↔灰度 之间跳**，到不了二值化/反色，
与演示脚本"**K1 依次切换**"不符。

**修正**：KEY0 短按改为 `O_mode <= O_mode + 1`（2 位自然回绕）⇒ **0→1→2→3→0 依次循环**；
KEY1 专职 AE 调节（长按透给 `ae_set`），不再改模式。

`tb_key_mode_ctrl.v` 已同步重写，**15/15 项全过**：

| 用例 | 检查 |

| T1 KEY0 短按 | 0 → 1 ✅ |
| T2 连续短按 | 1 → 2 → 3 → **0（回绕）** ✅ |

| R4 | 全局 SWNS 由 1.182 降到 **0.702 ns** | 仍远超 0.5 ns 警戒线、**0 违例**；如需可给 `u_hdmi_mixer` 再打一拍 |
| R5 | 交付物里仍有 `anlogic_logo_rom.v`（已被 P1b 取代的旧 Logo ROM） | 无害（`.al` 未登记，不参与编译）|

| R7 | `key_mode_ctrl.v` 改为循环后，**KEY2 不再控制任何模式** | 这是有意设计（KEY2 专职 AE）；若希望 KEY2 也参与（如切换二值化阈值），可后续扩展 |
